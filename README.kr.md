# WinCMux

[English](README.md) · [Windows 빌드](../../actions) · [성능 평가](docs/evaluation.md)

WinCMux는 Codex CLI, Claude Code, PowerShell 등을 여러 pane에서 쓰는 Windows 터미널 앱입니다. Tauri·WebView2·xterm.js 화면을 Rust와 Windows ConPTY에 연결합니다. 설치된 앱은 자체 코어를 실행하는 데 Node.js가 필요 없습니다.

![WinCMux Tauri 0.2.1의 터미널 분할 화면과 하단 입력창](assets/view.png)

*WinCMux Tauri 0.2.1에서 임시 워크스페이스와 예제 출력을 사용해 캡처한 화면입니다.*

- 터미널을 분할하고 워크스페이스와 그룹으로 정리합니다. 실행 중인 pane을 숨겼다가 다시 열 수 있습니다.
- 빈 pane에서 아이콘이 있는 Claude Code·Codex·Gemini·PowerShell 카드를 선택해 실행합니다. 상단 **실행 설정** 또는 **목록 관리**에서 이름·명령어·아이콘·순서·기본 도구를 추가·수정·삭제할 수 있습니다. 목록은 이 PC의 사용자 설정에 저장되며 모든 워크스페이스에서 공유됩니다. **Start**는 선택 화면에서 기본 도구에 먼저 초점을 맞춥니다.
- 선택한 pane 하단 입력창에서 작성하고 **Ctrl+Enter** 또는 **전송 / 대기열**로 해당 터미널의 에이전트 대기열에 추가합니다. 입력 가능하면 곧바로, 작업 중이면 완료 후 순서대로 제출합니다. pane별 초안은 전환 및 분할 시 유지됩니다.
- 여러 화면 줄에 걸친 URL을 선택해 **Ctrl+C**를 누르면 주소가 한 줄로 복사됩니다. 일반 텍스트의 줄바꿈은 유지됩니다.
- 세션 기록과 Codex·Claude 재개 명령을 찾고, Windows 알림과 워크스페이스의 에이전트 지침·텍스트·이미지 자료를 관리합니다.
- 각 터미널에서 작업 완료 후 또는 지정 시각에 한 번 보내는 **후속 입력**을 예약합니다. 훅 연결은 선택 사항입니다. [감지 및 전송 조건](docs/agent-hooks.md)

![한글과 여러 줄 초안을 표시한 WinCMux 입력창](assets/prompt-editor.png)

**Ctrl+Enter**로 추가한 대기열은 각 입력창 바로 위에 표시됩니다. 에이전트가 없는 일반 터미널에서는 기존처럼 바로 제출합니다. **삽입만**은 내용을 넣고 제출을 기다립니다. 입력창을 비운 상태에서 **터미널 제출**을 누르면 터미널의 현재 입력을 제출합니다.

## 0.2.94 파일 보기·터미널 그룹·알림 개선

파일 보기에서 Git 변경 목록을 페이지로 탐색하고 파일 내용까지 검색할 수 있습니다. 코드 미리보기는 언어를 자동 감지하고 결과를 표시하며, 언어 빠른 검색·파일 내 검색·Markdown 문서 보기를 지원합니다. Python을 포함한 언어 강조는 앱에 내장되어 있고 Windows 줄바꿈 파일에도 적용됩니다. 새 터미널은 실행할 도구를 선택한 뒤 시작하며, 그룹 안에서 만든 pane과 분할 pane은 그 그룹에 남습니다. 같은 한도 알림은 중복 등록하지 않고 지난 자동 알림은 정리합니다. [Windows x64 설치 파일](https://github.com/sungreong/wincmux/releases/tag/v0.2.94)을 받을 수 있습니다.

## 0.2.92 워크스페이스 중복 확인창

같은 경로나 폴더 이름으로 워크스페이스를 생성하면 앱 안에 확인창이 열립니다. 기존 워크스페이스의 이름과 경로를 보여 주며, **취소**하면 생성하지 않고 **그래도 생성**을 눌러야 중복 생성이 진행됩니다.

## 0.2.91 중복 확인과 폴더 경로

워크스페이스 생성 폼은 이름 옆에 폴더 선택·생성 아이콘을 배치하고, 아래 줄에서 폴더 경로를 넓게 표시합니다. 같은 경로 또는 같은 폴더 이름의 워크스페이스가 있으면 기존 경로를 보여 주고 생성 여부를 확인합니다. 상세 보기에서 폴더 경로를 줄바꿈해 표시하며 누르면 복사합니다. 한 줄·요약 보기에서도 워크스페이스 `⋯` 메뉴에서 전체 경로를 확인하고 복사할 수 있습니다.

## 0.2.90 워크스페이스 삭제 확인

워크스페이스를 삭제할 때 실행 중인 터미널이 있으면 개수를 보여 주고 재확인합니다. 승인하면 해당 워크스페이스의 터미널과 하위 작업을 종료한 뒤 삭제합니다. 실행 중인 터미널이 없으면 확인창 없이 바로 삭제합니다. 디스크의 프로젝트 폴더와 파일은 삭제하지 않습니다.

## 0.2.89 사이드바 정리

상단의 중복된 **완전히 종료** 버튼을 제거했습니다. 창의 X 또는 Alt+F4에서 **완전히 종료**, **창만 닫기**, **취소**를 선택할 수 있습니다. 노트는 기본으로 접혀 있고 펼침 상태가 저장됩니다. 워크스페이스는 마지막 폴더명이 정확히 같은 항목끼리만 자동으로 묶으며, 묶음을 접거나 펼칠 수 있습니다. 이미 등록된 경로로 새 워크스페이스를 만들 때는 확인을 요청합니다. 목록은 **한줄·요약·상세** 세 가지로 볼 수 있습니다.

## 0.2.88 Windows 트레이 아이콘 개선

백그라운드 코어의 트레이 아이콘을 Windows 기본 그림 대신 WinCMux 아이콘으로 표시합니다. 16~48px 전용 이미지가 포함된 다중 크기 `.ico`를 사용해 작은 트레이와 고해상도 화면에서 선명도를 높였습니다.

## 0.2.87 MCP 그룹·pane 제어

MCP에서 워크스페이스의 그룹을 조회·생성하고, pane을 가로/세로로 나눈 뒤 새 pane에 Claude·Codex·PowerShell 터미널을 그룹 지정하여 시작할 수 있습니다. 실행 중인 터미널의 그룹 이동도 지원합니다. 앱이 열려 있으면 MCP 변경 사항이 화면에 반영됩니다. 자세한 호출 방법은 [MCP 도구 문서](bridge/mcp/README.md)를 참고하세요.

## 0.2.86 창 닫기 선택

창의 X를 누르면 **완전히 종료**, **창만 닫기**, **취소** 중 선택합니다. 완전히 종료는 실행 중인 터미널과 하위 작업을 종료하고, 창만 닫기는 UI를 닫되 백그라운드 코어와 작업을 유지합니다.

## 0.2.85 대화 이력 정렬

**이전 대화 불러오기**에서 최근 수정순·오래된순·대화 파일 크기 큰순·작은순으로 정렬합니다. 파일 크기는 Claude/Codex 원본 대화 파일의 바이트 수이며, 메시지 수나 토큰 수를 뜻하지 않습니다. 정렬 방식은 이 PC의 앱에 저장됩니다. 메시지 수는 두 도구가 공통 메타데이터로 제공하지 않아 정렬 기준에 포함하지 않았습니다.

## 0.2.84 대화 이력 정리

**이전 대화 불러오기**에서 Claude Code와 Codex 대화를 숨기거나 즐겨찾기할 수 있습니다. 숨긴 대화는 **숨긴 대화** 필터에서 다시 표시할 수 있으며 원본 대화 파일은 삭제되지 않습니다. 시작일·종료일, 즐겨찾기 필터, 10/20/50개 페이지 이동과 **간결하게** 표시를 지원합니다. 숨김·즐겨찾기·표시 밀도·페이지 크기는 이 PC의 앱에 저장됩니다.

## 0.2.83 파일·Git·Agent 보기

![0.2.83 파일 검색과 미리보기](assets/workspace-search-0.2.83.png)

워크스페이스를 선택한 뒤 **파일 보기** 버튼 또는 워크스페이스의 빠른 메뉴에서 **Files**, **Git diff**, **Agent Assets**를 누릅니다. 터미널 옆에 뷰어가 열리며, 상단 **파일 · Git · Agent** 탭으로 전환합니다.

- **파일:** 폴더 트리를 펼쳐 텍스트·이미지를 미리 봅니다. 이름/경로 패턴과 파일 내용을 검색하고, 폴더를 선택하면 **선택 폴더에서 검색**할 수 있습니다. 파일을 선택해 **파일 복사**를 누른 뒤 대상 폴더에서 **여기에 붙여넣기**를 누릅니다. 새로고침해도 펼친 폴더와 현재 선택이 유지됩니다.
- **Git:** 스테이징된 변경, 스테이징 전 변경, 추적되지 않은 파일을 나눠 보여줍니다. 같은 파일에 두 종류의 변경이 있으면 각각 선택해 색상이 적용된 diff를 봅니다.
- **Agent:** 작업공간에 실제로 있는 에이전트 관련 파일을 `.agents`, `.codex`, `.claude` 등 실제 폴더별로 묶습니다. 각 그룹을 접고 펼칠 수 있고, 편집 가능한 파일은 **편집 → 저장**으로 수정합니다.
- 목록에서 **↑/↓**로 파일을 이동하고, 미리보기의 화살표나 **Alt+↑/↓**로 이전·다음 파일을 선택합니다. 내용 검색은 파일당 256KB, 전체 20MB, 최대 5초로 제한됩니다.

## 0.2.6 변경점

- Codex·Claude 훅을 설정하지 않아도 실행 중인 에이전트 프로세스와 터미널의 완료/입력 대기 상태를 감지해 후속 입력을 예약할 수 있습니다. 에이전트가 종료되면 대기 예약을 실패로 표시합니다.
- 훅이 연결된 세션에서는 기존 훅 신호를 우선 사용합니다. 새 Claude·Codex 세션은 살아 있는 에이전트와 시작 입력창을 확인하면 첫 완료 신호 없이도 전송합니다. 작업 시작 후에는 새 완료 신호를 기다립니다.
- Codex가 화면을 다시 그려 원시 출력에 줄바꿈이 없어도 화면의 `done` 표시와 입력 프롬프트를 확인합니다. CLI 입력줄에 미제출 글이 있어도 초안을 분리한 뒤 예약 문구를 전송합니다. 예약 창을 닫아도 입력창 위에 대기열이 보입니다.

## 0.2.5 변경점

- **후속 입력 예약** 버튼을 터미널 헤더에서 각 터미널 아래 메시지 입력창 옆으로 옮겼습니다. 예약 패널은 해당 입력창 위에 열립니다.

## 0.2.4 변경점

- 각 터미널 헤더의 **후속 입력** 버튼에서 그 세션의 예약을 작성·확인합니다. 입력 패널은 해당 터미널 안에 열리고, 다른 터미널의 예약은 섞이지 않습니다.
- **현재 작업 완료 후**는 예약 이후 새 완료 훅을 받으면 한 번 전송합니다. 이미 완료된 상태라면 다음 작업 완료를 기다립니다. **지정 시각 이후**는 해당 시각이 지나고 에이전트가 입력 가능한 상태가 될 때 전송합니다.
- 기존 예약은 스키마 12로 옮기며, 마이그레이션 전 DB를 `pre-v12-*.bak`으로 백업합니다. [훅 연결 및 전송 조건](docs/agent-hooks.md)

## 0.2.3 변경점

- 상단 **대화 이력**, 빈 터미널의 **이전 대화 불러오기**, Sessions 메뉴에서 프로젝트의 Claude·Codex 저장 대화를 조회합니다. 제목·저장 시각·폴더·대화 ID를 표시하고 검색·도구 필터·하위 폴더 포함·새로고침을 지원합니다.
- Claude의 로컬 JSONL, Codex의 대화 파일·제목 인덱스·읽기 전용 DB를 조회합니다. 원본 대화를 앱 DB로 복사하거나 수정·삭제하지 않습니다. `CLAUDE_CONFIG_DIR`·`CODEX_HOME`을 따르며, WSL·다른 사용자 계정의 이력은 자동 수집하지 않습니다. 도구가 삭제했거나 저장하지 않은 대화는 복원할 수 없습니다.
- 선택한 대화는 저장된 실행 폴더에서 `claude --resume <ID>` 또는 `codex resume <ID>`로 엽니다. 실행 중이거나 복원할 세션이 있는 터미널은 유지하고 새 터미널을 분할합니다. 각 도구의 기본 resume 선택기도 열 수 있습니다. CLI 설치·로그인과 대화 보관은 해당 도구가 관리합니다.
- 공백이 붙은 `Usagelimitreached·continuingautomaticallyat7:50pm` 안내와 경고 아이콘을 인식합니다. `/usage-credits to continue now`는 초기화 시각이 아닌 선택지로 구분합니다.
- 날짜 없는 시각은 문구가 처음 표시된 날짜·시간대에서 다음 해당 시각으로 예약합니다. 오후에 나온 `3am`은 다음 날, 아직 지나지 않은 `7:50pm`은 당일입니다. 현재와 같은 분은 도착한 알림으로 처리하며, 명시된 과거 날짜를 임의로 내일로 바꾸지는 않습니다.
- 최초 감지 시각을 저장·표시하고 상대 시간과 `now`를 그 시각에 고정합니다. 문구를 나누어 수신하거나 자정을 넘어 처리해도 날짜가 바뀌지 않습니다. `continuing automatically now`는 즉시 알림이며, 크레딧 안내의 `now`는 예약을 앞당기지 않습니다. 기존 DB는 `pre-v10-*.bak`으로 백업합니다.

## 0.2.2 변경점

- 빈 터미널에서 Claude Code·Codex·Gemini·PowerShell을 선택하고 **실행 설정**에서 실행 목록을 관리합니다.
- **예약 알림**에서 알림을 직접 등록·수정·취소·삭제합니다. 알림은 Windows 배너와 앱 내부에 표시됩니다.
- Claude·Codex·Gemini의 사용 한도 문구에서 명확한 초기화 시각이나 재시도 간격을 감지하면 자동 예약합니다. 동일 세션·도구·한도·초기화 시각의 반복 출력은 중복 등록하지 않습니다. 계정이 확인되지 않은 서로 다른 세션은 합치지 않습니다.
- 시간이나 날짜가 모호하면 **시간 지정 필요**로 표시합니다. 감지 규칙에 맞지 않는 문구는 수동으로 등록할 수 있습니다. 기본 시간대는 `Asia/Seoul`이며 설정에서 변경할 수 있습니다.
- 창을 닫아도 예약이 남아 있으면 코어가 유지됩니다. 절전 중 지난 알림은 복귀 때, PC 종료·완전 종료 중 지난 알림은 앱을 다시 실행할 때 표시합니다. 예약 알림은 초기화 예정 시각 안내이며 실제 서비스 사용 가능 여부를 보장하지 않습니다.
- 기존 크기 동기화·한글 폭 계산 개선을 포함합니다. 데이터베이스 변경 전 `pre-v9-*.bak` 백업을 생성합니다.

## 0.2.1 변경점

화면과 실행 코어를 분리했습니다. 창의 X에서 **창만 닫기**를 선택하면 터미널·셸·에이전트·개발 서버는 `wincmux-core.exe`에서 계속 실행됩니다. 다시 열면 기존 작업과 터미널 화면에 연결됩니다. 화면이 닫힌 동안에는 전용 WebView2를 유지하지 않습니다.

| 상황 | 동작 |
|---|---|
| X 버튼·Alt+F4 | 완전히 종료·창만 닫기·취소 중 선택 |
| 화면 앱 충돌 | 실행 중인 작업 유지 |
| 다시 실행 | 기존 세션·화면·숨긴 터미널·미확인 결과 복원 |
| 승인 대기·완료 | Windows 알림과 트레이로 확인, 클릭해서 해당 작업으로 이동 |
| 화면·실행 중인 터미널·예약 알림이 모두 없음 | 30초 후 코어 종료 |
| X 메뉴의 ‘완전히 종료’ | 실행 중인 터미널과 하위 작업 종료 |
| 작업 실행 중 업데이트·삭제 | 작업을 강제 종료하지 않고 설치·삭제 중단 |

PC 재부팅·로그아웃·코어 자체 충돌 후 프로세스를 되살리는 기능은 포함하지 않습니다. 다음 실행에서 이전 작업의 종료 사실을 표시하며, 기록된 명령이나 대화 재개를 사용자가 선택합니다.

화면은 색상·글꼴·상태·간격을 디자인 토큰으로 관리합니다. 4px 간격과 공통 모서리를 사용하고, 작업 중 상태와 결과 확인 버튼을 구분했습니다. 반복 설명은 도움말과 툴팁으로 옮겼습니다. [디자인 점검과 컴포넌트 규칙](docs/ui-design.md)

## 백그라운드 실행 확인

1. WinCMux의 PowerShell 터미널에서 아래 명령을 실행하고 첫 PID를 기록합니다.

   ```powershell
   $PID
   while ($true) {
     Get-Date -Format 'HH:mm:ss'
     Start-Sleep 2
   }
   ```

2. X 버튼으로 창을 닫고 작업 관리자 → 세부 정보에서 `wincmux-tauri.exe`가 종료되고 `wincmux-core.exe`와 기록한 PowerShell PID가 유지되는지 확인합니다.
3. 10초 후 다시 열어 닫혀 있던 동안의 출력이 이어지는지 확인합니다. `Ctrl+C` 후 `$PID`가 처음 값과 같으면 같은 작업에 재연결된 것입니다.
4. 충돌 상황은 작업 관리자에서 **`wincmux-tauri.exe`만** 종료한 뒤 같은 방법으로 확인합니다.

자동 테스트에서는 정상·강제 종료, 숨긴 세션, 알림 이동, 정상·대체 화면 복원과 업데이트 보호를 확인했습니다. 코어 분리 전후 3회 측정에서 6개 패널의 앱·코어 메모리 증가 중앙값은 10.35MiB였습니다. 화면 없는 코어는 테스트 터미널 6개에서 6.94MiB, 60초 유휴 CPU는 0.155%였습니다. 실제 Codex·Claude의 메모리나 응답 속도를 뜻하지 않습니다. [측정 조건·결과·한계](docs/background-core-evaluation.md)

## 초기 Electron → Tauri 전환 측정

같은 Windows PC에서 두 번씩 실행했을 때 x64 설치 파일은 **95.61 MiB → 3.66 MiB**, pane 6개 기준 앱·코어 메모리는 **491–504 MiB → 391 MiB**, 선택 pane의 입력 왕복 P95는 **16.0–16.3 ms → 10.1–11.3 ms**였습니다. 두 구현 모두 한글, 연속 공백, **18,000줄의 출력**을 보존했습니다. [측정 조건과 검증 범위](docs/evaluation.md)

현재 백그라운드 코어 분리의 3회 비교는 [코어 평가](docs/background-core-evaluation.md), 0.2.1 화면 정리는 [디자인 점검](docs/ui-design.md)을 참고하세요.

## Windows에서 개발하고 빌드하기

Node.js 20 이상, Rust MSVC 도구 체인과 rustfmt, Visual Studio C++ Build Tools, WebView2가 필요합니다.

```powershell
npm ci
npm run dev
npm run lint
npm test
npm run package:win
npm run test:ui
npm run test:runtime
npm run test:lifecycle
```

x64 NSIS 설치 파일은 `apps/desktop-tauri/src-tauri/target/release/bundle/nsis/`에 생성됩니다. UI 테스트는 빌드된 릴리스 실행 파일과 임시 WebView2 프로필을 사용합니다.

DB는 `%APPDATA%\WinCMux-Tauri\wincmux.db`에 저장됩니다. 이전 SQLite DB를 가져오려면 두 앱을 종료하고 해당 위치에 복사하세요. Electron 소스는 Git 태그 [v0.1.0](../../tree/v0.1.0)에서 확인할 수 있습니다.
