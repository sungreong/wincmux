# WinCMux

[English](README.md) · [최신 Windows x64 설치 파일](https://github.com/sungreong/wincmux/releases/latest) · [변경 이력](CHANGELOG.kr.md) · [Windows 빌드](../../actions) · [성능 평가](docs/evaluation.md)

WinCMux는 Codex CLI, Claude Code, PowerShell 등을 여러 pane에서 쓰는 Windows 터미널 앱입니다. Tauri·WebView2·xterm.js 화면을 Rust와 Windows ConPTY에 연결합니다. 설치된 앱은 자체 코어를 실행하는 데 Node.js가 필요 없습니다.

![WinCMux Tauri 0.2.1의 터미널 분할 화면과 하단 입력창](assets/view.png)

*WinCMux Tauri 0.2.1에서 임시 워크스페이스와 예제 출력을 사용해 캡처한 화면입니다.*

- 터미널을 분할하고 워크스페이스와 그룹으로 정리합니다. 그룹에서 새 터미널을 만들거나 pane을 분할해도 그 그룹에 남습니다. 실행 중인 pane을 숨겼다가 다시 열 수 있습니다.
- 빈 pane에서 아이콘이 있는 Claude Code·Codex·Gemini·PowerShell 카드를 선택해 실행합니다. 상단 **실행 설정** 또는 **목록 관리**에서 이름·명령어·아이콘·순서·기본 도구를 추가·수정·삭제할 수 있습니다. 목록은 이 PC의 사용자 설정에 저장되며 모든 워크스페이스에서 공유됩니다. **Start**는 선택 화면에서 기본 도구에 먼저 초점을 맞춥니다.
- 선택한 pane 하단 입력창에서 작성하고 **Ctrl+Enter** 또는 **전송 / 대기열**로 해당 터미널의 에이전트 대기열에 추가합니다. 입력 가능하면 곧바로, 작업 중이면 완료 후 순서대로 제출합니다. pane별 초안은 전환 및 분할 시 유지됩니다.
- 여러 화면 줄에 걸친 URL을 선택해 **Ctrl+C**를 누르면 주소가 한 줄로 복사됩니다. 일반 텍스트의 줄바꿈은 유지됩니다.
- 세션 기록과 Codex·Claude 재개 명령을 찾고, Windows 알림과 워크스페이스의 에이전트 지침·텍스트·이미지 자료를 관리합니다.
- 각 터미널에서 작업 완료 후 또는 지정 시각에 한 번 보내는 **후속 입력**을 예약합니다. 훅 연결은 선택 사항입니다. [감지 및 전송 조건](docs/agent-hooks.md)

![한글과 여러 줄 초안을 표시한 WinCMux 입력창](assets/prompt-editor.png)

대기열은 각 입력창 바로 위에 표시됩니다. 제출하거나 취소한 항목은 목록에서 바로 사라지며, 실패 항목은 입력창으로 복원하거나 지울 수 있습니다. 에이전트가 없는 일반 터미널에서는 **Ctrl+Enter**로 바로 제출합니다. **삽입만**은 내용을 넣고 제출을 기다립니다. 입력창을 비운 채 **터미널 제출**을 누르면 터미널에 작성된 내용을 제출합니다.

## 로컬 Docker

상단 **로컬 Docker**를 열고 이 PC에서 실행 중인 Linux 컨테이너를 선택합니다. 폴더 아이콘으로 컨테이너 내부 프로젝트를 열면 터미널과 파일·Git 보기가 그 폴더를 사용합니다. 마지막에 연 컨테이너와 폴더는 이 PC에 저장됩니다. 컨테이너 검색 창의 **새로 고침**으로 실행 중인 대상을 다시 불러올 수 있습니다.

## 원격 SSH 작업공간

상단의 **원격 SSH**에서 Windows의 `%USERPROFILE%\.ssh\config`에 등록한 별칭을 고르거나, **직접 입력**에서 호스트·사용자·포트와 선택 사항인 개인 키를 지정합니다. **연결 테스트**의 결과는 설정 화면에 표시됩니다. **연결**에 성공하면 원격 작업공간이 열리고 서버가 저장 목록에 추가됩니다. 신규 서버 키는 관리자에게 받은 지문과 비교한 후 신뢰하세요. 실제 연결에서 **다음 연결에 비밀번호 사용**을 선택하면 로그인에 성공한 비밀번호를 Windows 자격 증명 관리자에 저장합니다.

**VS Code에서 SSH 설정 열기**로 `config`를 편집할 수 있습니다. WinCMux 창으로 돌아오거나 **목록 새로 고침**을 누르면 별칭 목록이 업데이트됩니다. 직접 입력한 연결은 테스트에 성공한 뒤 **Windows SSH에 저장**으로 별칭을 추가할 수 있습니다.

연결 후 폴더 아이콘으로 작업 폴더를 엽니다. 대상 옆의 **Docker 컨테이너 접속** 아이콘에서 컨테이너와 내부 폴더를 고르면 별도 탭에서 선택한 도구가 새로 실행됩니다. Docker 탭의 **닫기**는 해당 탭의 터미널을 종료합니다. 실행 중인 컨테이너와 SSH 서버 연결은 유지됩니다. **폴더 저장** 아이콘을 누르면 다음 SSH 연결 때 그 위치를 다시 엽니다.

**+ Claude Code**와 **+ Codex**는 선택한 환경에 설치된 CLI를 새 터미널에서 실행합니다. 메시지를 전송하면 터미널의 입력 상태를 확인하고, 작업 중이면 해당 pane의 대기열에서 다음 입력 시점을 기다립니다.

SSH와 로컬 Docker의 pane은 창 높이에 맞춰 조절됩니다. 출력은 pane 안에서 스크롤되고 하단 입력창은 제자리에 표시됩니다. pane 아이콘으로 오른쪽·아래 분할, 글자 크기 조절, 파일 보기, 닫기를 실행합니다. `Ctrl+Alt+Q`로 선택한 pane을 닫을 수도 있습니다. 상단 종 아이콘은 작업 완료·입력 요청·사용 한도 알림을, 시계 아이콘은 예약 알림을 엽니다.

**VS Code에서 열기**는 Windows SSH 별칭과 VS Code의 Remote - SSH 확장을 사용합니다. 컨테이너 작업공간이면 VS Code에서 **Dev Containers: Attach to Running Container**를 실행해 같은 컨테이너를 선택합니다. WinCMux의 Docker 접속에는 원격 계정의 Docker 접근 권한과 대상 컨테이너의 `sh`가 필요합니다.

## MCP 제어

MCP는 로컬 작업공간에서 사용할 수 있습니다. 원격 SSH와 Docker 컨테이너는 별도 창에서 열리며 세션 제어와 화면 캡처의 범위에서 제외됩니다.

상단 **MCP**에서 로컬 서버 연결 명령과 지원 도구를 확인할 수 있습니다. MCP 클라이언트에서 워크스페이스·터미널 pane을 조회하고, 그룹 생성·이름 변경·삭제, 그룹에서 터미널 열기, pane 분할·선택, 터미널 출력 읽기와 후속 입력 예약을 할 수 있습니다. 연결 방법과 도구 인수는 [MCP 도구 안내](bridge/mcp/README.md)를 참고하세요.

## 파일·Git·Agent 보기

![0.2.83 파일 검색과 미리보기](assets/workspace-search-0.2.83.png)

워크스페이스를 선택한 뒤 **파일 보기** 버튼 또는 워크스페이스의 빠른 메뉴에서 **Files**, **Git diff**, **Agent Assets**를 누릅니다. 터미널 옆에 뷰어가 열리며, 상단 **파일 · Git · Agent** 탭으로 전환합니다.

- **파일:** 폴더 트리에서 텍스트·이미지·Markdown을 미리 봅니다. 이름/경로 패턴과 파일 내용을 검색하고, 폴더를 선택하면 **선택 폴더에서 검색**할 수 있습니다. 코드에서는 자동 감지 언어와 구문 색상을 확인하고 언어를 빠르게 검색할 수 있습니다. 파일 내 검색은 **Ctrl+F**로 엽니다. 파일을 선택해 **파일 복사**를 누른 뒤 대상 폴더에서 **여기에 붙여넣기**를 누릅니다. 새로고침해도 펼친 폴더와 현재 선택이 유지됩니다.
- **Git:** 스테이징된 변경, 스테이징 전 변경, 추적되지 않은 파일을 나눠 보여주며 변경이 많으면 페이지로 이동합니다. 같은 파일에 두 종류의 변경이 있으면 각각 선택해 색상이 적용된 diff를 봅니다.
- **Agent:** 작업공간에 실제로 있는 에이전트 관련 파일을 `.agents`, `.codex`, `.claude` 등 실제 폴더별로 묶습니다. 각 그룹을 접고 펼칠 수 있고, 편집 가능한 파일은 **편집 → 저장**으로 수정합니다.
- 목록에서 **↑/↓**로 파일을 이동하고, 미리보기의 화살표나 **Alt+↑/↓**로 이전·다음 파일을 선택합니다. 내용 검색은 파일당 256KB, 전체 20MB, 최대 5초로 제한됩니다.

## 백그라운드 코어와 창 닫기

로컬 Windows 터미널은 화면과 실행 코어가 분리되어 있습니다. 메인 창의 X에서 **창만 닫기**를 선택하면 로컬 터미널·셸·에이전트·개발 서버는 `wincmux-core.exe`에서 계속 실행됩니다. 다시 열면 기존 작업과 터미널 화면에 연결됩니다. SSH와 Docker의 연결된 터미널 세션은 각 작업공간 창에서 관리합니다.

| 상황 | 동작 |
|---|---|
| X 버튼·Alt+F4 | 완전히 종료·창만 닫기·취소 중 선택 |
| 화면 앱 충돌 | 실행 중인 작업 유지 |
| 다시 실행 | 기존 세션·화면·숨긴 터미널·미확인 결과 복원 |
| 승인 대기·완료 | Windows 알림과 트레이로 확인, 클릭해서 해당 작업으로 이동 |
| 화면·실행 중인 터미널·예약 알림이 모두 없음 | 30초 후 코어 종료 |
| X 메뉴의 ‘완전히 종료’ | 실행 중인 터미널과 하위 작업 종료 |
| 작업 실행 중 업데이트·삭제 | 작업을 강제 종료하지 않고 설치·삭제 중단 |

PC 재부팅·로그아웃·코어 자체 충돌 후 프로세스를 되살리는 기능은 포함하지 않습니다. 다음 실행에서 이전 작업의 종료 사실을 표시하며, 기록된 명령이나 대화 재개를 사용자가 선택합니다.

화면은 색상·글꼴·상태·간격을 디자인 토큰으로 관리합니다. 4px 간격과 공통 모서리를 사용하고, 작업 중 상태와 결과 확인 버튼을 구분했습니다. 반복 설명은 도움말과 툴팁으로 옮겼습니다. [디자인 점검과 컴포넌트 규칙](docs/ui-design.md)

## 백그라운드 실행 확인

1. WinCMux의 PowerShell 터미널에서 아래 명령을 실행하고 첫 PID를 기록합니다.

   ```powershell
   $PID
   while ($true) {
     Get-Date -Format 'HH:mm:ss'
     Start-Sleep 2
   }
   ```

2. X 버튼으로 창을 닫고 작업 관리자 → 세부 정보에서 `wincmux-tauri.exe`가 종료되고 `wincmux-core.exe`와 기록한 PowerShell PID가 유지되는지 확인합니다.
3. 10초 후 다시 열어 닫혀 있던 동안의 출력이 이어지는지 확인합니다. `Ctrl+C` 후 `$PID`가 처음 값과 같으면 같은 작업에 재연결된 것입니다.
4. 충돌 상황은 작업 관리자에서 **`wincmux-tauri.exe`만** 종료한 뒤 같은 방법으로 확인합니다.

자동 테스트에서는 정상·강제 종료, 숨긴 세션, 알림 이동, 정상·대체 화면 복원과 업데이트 보호를 확인했습니다. 코어 분리 전후 3회 측정에서 6개 패널의 앱·코어 메모리 증가 중앙값은 10.35MiB였습니다. 화면 없는 코어는 테스트 터미널 6개에서 6.94MiB, 60초 유휴 CPU는 0.155%였습니다. 실제 Codex·Claude의 메모리나 응답 속도를 뜻하지 않습니다. [측정 조건·결과·한계](docs/background-core-evaluation.md)

## 초기 Electron → Tauri 전환 측정

같은 Windows PC에서 두 번씩 실행했을 때 x64 설치 파일은 **95.61 MiB → 3.66 MiB**, pane 6개 기준 앱·코어 메모리는 **491–504 MiB → 391 MiB**, 선택 pane의 입력 왕복 P95는 **16.0–16.3 ms → 10.1–11.3 ms**였습니다. 두 구현 모두 한글, 연속 공백, **18,000줄의 출력**을 보존했습니다. [측정 조건과 검증 범위](docs/evaluation.md)

현재 백그라운드 코어 분리의 3회 비교는 [코어 평가](docs/background-core-evaluation.md), 0.2.1 화면 정리는 [디자인 점검](docs/ui-design.md)을 참고하세요.

## Windows에서 개발하고 빌드하기

Node.js 20 이상, Rust MSVC 도구 체인과 rustfmt, Visual Studio C++ Build Tools, WebView2가 필요합니다.

```powershell
npm ci
npm run dev
npm run lint
npm test
npm run package:win
npm run test:ui
npm run test:runtime
npm run test:lifecycle
```

x64 NSIS 설치 파일은 `apps/desktop-tauri/src-tauri/target/release/bundle/nsis/`에 생성됩니다. UI 테스트는 빌드된 릴리스 실행 파일과 임시 WebView2 프로필을 사용합니다.

DB는 `%APPDATA%\WinCMux-Tauri\wincmux.db`에 저장됩니다. 이전 SQLite DB를 가져오려면 두 앱을 종료하고 해당 위치에 복사하세요. Electron 소스는 Git 태그 [v0.1.0](../../tree/v0.1.0)에서 확인할 수 있습니다.

[아키텍처](docs/architecture.md) · [기능](docs/features.md) · [JSON-RPC 브리지](bridge/README.md)
