# 에이전트 훅과 후속 입력

WinCMux는 터미널 출력과 OSC 7501로 에이전트 상태를 추정합니다. Codex CLI 또는 Claude Code 훅을 연결하면 시작, 작업, 승인 대기, 완료를 해당 에이전트의 신호로 표시합니다. 터미널 프로세스의 실행 여부는 별도로 관리합니다.

## 선택 사항: 훅 연결

1. 사용할 터미널 아래 입력창의 **후속 입력 예약** 버튼을 누르고 **Codex·Claude 훅 연결 방법**을 펼칩니다. 실행 중인 `wincmux-core.exe`의 실제 경로가 들어간 JSON을 복사합니다.
2. Codex는 `%USERPROFILE%\.codex\hooks.json`, Claude Code는 `%USERPROFILE%\.claude\settings.json`의 기존 `hooks` 객체에 해당 이벤트 항목을 **병합**합니다. 다른 훅이나 설정을 지우지 않습니다. 앱은 이 설정 파일을 직접 수정하지 않습니다.
3. Codex가 훅 신뢰 확인을 표시하면 명령과 경로를 검토하고 승인합니다. 새 WinCMux 터미널에서 에이전트를 실행해 한 번 대화합니다. pane 상태 툴팁에 훅 제공자·수신 횟수·최근 이벤트가 나타나면 연결됐습니다. 수신 전에는 화면/OSC 추정 상태로 표시합니다.

훅은 입력 JSON에서 세션 ID, 턴 ID, 이벤트 이름만 읽어 로컬 코어 파이프로 보냅니다. 프롬프트, 도구 입력, 응답 내용은 전송하지 않습니다. 코어는 세션 토큰과 훅 프로세스의 터미널 자손 관계를 확인합니다. 에이전트 훅 명령이 실패해도 에이전트 작업을 멈추지 않습니다.

Codex 훅 형식과 신뢰 절차는 [Codex Hooks](https://learn.chatgpt.com/docs/hooks), Claude Code 설정 및 이벤트는 [Claude Code Hooks](https://code.claude.com/docs/en/hooks)를 따릅니다. CLI 버전이나 실행 환경에 따라 훅이 실행되지 않을 수 있으므로 실제 수신 표시로 확인합니다.

## 후속 입력 예약

각 터미널의 입력창에서 **Ctrl+Enter**를 누르면 입력 가능한 상태에서 바로 제출하고, 작업 중에는 대기열에 추가합니다. 대기열은 입력창 위에 표시됩니다. 제출하거나 취소한 항목은 바로 사라지고, 실패 항목은 복원하거나 지울 수 있습니다. **후속 입력 예약** 패널에서는 완료 후 또는 지정 시각 이후 전송을 설정할 수 있습니다. 훅 연결은 선택 사항이며, 연결된 터미널에서는 훅 완료 신호를 우선 사용합니다.

- **현재 작업 완료 후:** 예약 이후 새 완료 상태를 기다립니다. 이미 완료된 상태에서 예약했다면 다음 작업의 완료를 기다립니다. 훅이 있으면 새 `Stop` 신호를 사용하고, 없으면 터미널의 완료/입력 대기 표시를 감지합니다.
- **지정 시각 이후:** 시각이 지난 뒤 에이전트가 완료되어 입력 가능한 상태면 한 번 전송합니다. 아직 작업 중이거나 승인 대기 중이면 완료를 기다립니다.

두 방식 모두 예약을 해당 터미널 세션과 에이전트 프로세스에 고정합니다. 전송 직전 동일한 살아 있는 프로세스, 완료 후 입력 대기 상태, bracketed paste 모드를 확인합니다. 터미널 출력에서 완료를 확신할 수 없으면 계속 기다립니다. 일시 정지·재개·취소할 수 있습니다.

새로 시작한 Claude·Codex는 화면 하단의 실제 빈 입력창과 에이전트 고유 화면 표시를 확인하면 첫 완료 신호 없이 입력 가능합니다. Gemini CLI는 기본 동적 터미널 제목의 `◇ Ready` 신호와 `Type your message or @path/to/file` 입력창을 함께 확인합니다. Claude의 `Try "…"`와 Gemini의 입력 안내 문구는 빈 입력창으로 처리합니다. 첫 작업을 제출한 뒤에는 이 시작 상태를 다시 사용하지 않습니다.

Codex가 화면을 다시 그리면 화면의 `for 25s · done` 형태의 완료 표시와 입력 프롬프트를 함께 확인합니다. Gemini는 동적 제목이 `✦ Working` 또는 `⏲ Working`에서 `◇ Ready`로 바뀌고 입력창이 보이면 완료로 확인합니다. 일반 대기열은 CLI에 실제 초안이 남아 있을 때 입력창이 비워질 때까지 기다립니다. 명시적인 후속 예약에서 초안을 분리할 때는 Codex·Gemini의 Ctrl+C 또는 Claude의 Ctrl+S를 사용합니다. 빈 입력줄이 확인되면 예약 문구를 전송하고, 확인에 실패하면 대기열 항목을 복원할 수 있게 남깁니다.

전송 직전 예약을 DB에서 선점합니다. 전송 중 코어가 종료되거나 제출 결과가 불확실하면 재전송하지 않고 실패로 기록합니다. 터미널이나 에이전트가 종료되면 남은 예약은 실패로 기록합니다. 이 기능은 사용량 제한 **예약 알림**과 독립적입니다.

터미널 제어문자는 예약 문구에 넣을 수 없습니다. `!` 또는 `/`로 시작하는 내용도 CLI의 셸·슬래시 명령 모드와 충돌할 수 있어 거부합니다.
